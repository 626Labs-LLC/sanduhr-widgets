# Contributing a pack

The catalog is curated. Anyone can propose a pack; a maintainer reviews every one before it ships.
Format v1 is data only, so a review is about art, taste and rights, not about reading code.

## The flow

1. Fork, then create `packs/<id>/` (lowercase kebab-case id, 3 to 40 characters, same as the
   folder name). Start from a pack of the same kind in `packs/`.
2. Write `pack.json`, the assets, and a `LICENSE` file with your license's full text.
   `docs/FORMAT.md` is the spec; `schema/` has the JSON shapes.
3. Run the checks locally. Python 3 is all you need, no pip:

   ```
   python tools/validate.py packs/<id> --strict
   python tools/test_validate.py
   ```

4. Open a pull request with one pack per PR. CI runs the same two commands. Say in the PR who made
   the art and how (hand-drawn, generated by a script you wrote, and so on).
5. A maintainer reviews, may ask for changes, and merges. Packs ship with the next tagged release,
   which signs the catalog. Merging does not publish by itself.

Updating a pack: bump `version` (semver). The catalog serves the latest version of each id.

## Rules

These are enforced by `tools/validate.py` where a machine can check them and by review where one
cannot.

- **Data only.** JSON, PNG, and TTF/OTF fonts. No scripts, executables, HTML, or SVG, ever.
- **No third-party marks or logos.** No Anthropic or Claude names or marks, no model names
  (Opus, Sonnet, Haiku, Fable and the like) used as branding, no studio characters, no brand
  logos, no recolors of someone else's sprites. If a reviewer would ask "whose is that?", it does
  not ship.
- **Original work, or work you have the right to relicense.** You hold the rights to every pixel
  and every color table you submit. "Found on the internet" is not a source.
- **License.** One of `MIT`, `CC-BY-4.0`, `CC0-1.0`, `Apache-2.0`, `OFL-1.1`, `BSD-3-Clause`,
  `ISC`, declared in `pack.json` and matched by the text in your pack's `LICENSE`. Fonts must be
  `OFL-1.1` or `Apache-2.0`, and keep their original family name under OFL reserved-name rules.
- **Limits.** Images PNG only, 2 MB and 4096 px a side at most; pack under 10 MB; no symlinks;
  paths stay inside the pack.
- **Taste.** Themes must lint clean under Sanduhr's own theme rules (contrast, a monochrome text
  ramp, a visible pace marker). Sprites need all nine required animations and every growth stage.
  No pure white (`#ffffff`) in sprites: it burns on OLED panels. Nothing that flashes harder than a
  slow pulse.
- **Honest descriptions.** What the pack is, in 200 characters or fewer, with no marketing claims
  and no names that are not yours.

## What review looks at

- Does it pass `--strict`, and does it look right in the app at 1x and at the declared `scale`?
- Provenance of the art and the license text.
- Anything that reads as another brand, game or character.
- Whether the pack does one thing (one kind per pack).

## Questions and security

Format questions: open an issue. Anything that looks like a malicious pack: see `SECURITY.md`,
not a public issue.
